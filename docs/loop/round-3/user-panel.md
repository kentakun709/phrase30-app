## 役4: 行動視点（毎日開いて何度も押す）
- **押す手間はほぼゼロで、ここは強い。** カード全体が押せて、前の音は止まって溜まらない（A）。
- **一番大きい摩擦は「自然な声にする」コスト。**
  - アプリを離れて設定アプリに行き、言語ごとにダウンロードし、戻ってくる。
  - 戻っても、声の一覧が新しくなるのは言語を切り替えた時か、端末から知らせが来た時だけ（app.js:129・243・271）。すぐ押すと前の声のまま鳴る恐れがある（C）。
- **毎回の起動でちらつく恐れ。**
  - 声の一覧が最初は空で届く端末だと、帯に「端末の音声の一覧をまだ読み込めていません…」と手順つきの長い案内が一瞬出る。同時に「声: なし（英語の声がこの端末にありません）」と出て、すぐ消える（app.js:84-89。待ち時間は無い）。
  - スクロール位置を戻した直後に画面が跳ねる（C）。
- **閉じた案内の扱い。**
  - 「鳴りませんでした」は言語を問わず1件として覚えるので、一度閉じるとその回の利用中は二度と出ない（app.js:101・274）。
  - 逆に「この端末に【タイ語】の音声が入っていません」は、閉じたことが次の日に残らない。声の無い端末では毎日出る（A）。
- **判定:**
  - 初日は全部の言語を押して回る。気に入った1言語だけ声を入れるかもしれない。
  - 周回2より画面がすっきりした分、1週目は持つ。2週目の頭に開かなくなる。
- **本音の理由（B/C）:**
  - 5言語中4つは簡易版の声のまま。
  - 直すには言語ごとに数百MBのダウンロードが要り、英語は直しても変わらないかもしれない。
  - 読めない文字を音だけで追うのは疲れる。

     - 英語は「英語（オーストラリア）」、スペイン語は「スペイン語（スペイン）」と、手順に地域まで書く。
     - 言語の中では高品質の声を優先する（NZに近い声より自然な声。要件は「自然な声を優先選択」、NZは「可能なら」）。
2. **9番と11番の注「自分が聞くなら〇〇に Japanese を」が、英語以外の5言語で英語のまま出る。**
   - 各言語の「日本語」に直すか、「日语」「일본어」のように例を出す（phrases.json の9・11番、10枚、A）。
   - 雑に作った印象を与え、信用を一番削る1行。

### P2
1. 帯の声の表示を短くする（例「声: オーストラリア英語（NZに近い声）」）。言語の注意と同じ話を二重に出さない。言語の注意の「→英→米の順」を消す（A）。

3. 声が無い時は「機械っぽい時は」の見出しを出さない。案内は帯か本文のどちらか1か所にまとめる（app.js:83-90、A）。
